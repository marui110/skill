# 人物模型构造法

## R — 原文 (Reading)

> "人物模型是一种强有力、多用途的设计工具，有助于克服困扰数字产品开发过程中的若干难题。为弹性用户设计就像给了产品团队许可，可以随心所欲地构建产品。人物模型必须代表特定用户而非弹性概念。"
>
> — Alan Cooper, 第3章

---

## I — 方法论骨架 (Interpretation)

人物模型（Persona）不是用户画像，不是用户标签，是设计决策的锚点。

8步构造法：
1. **按角色分组**：将访谈对象按工作角色或生活角色分类
2. **找行为变量**：识别区分不同用户的行为维度（不是人口统计维度）
3. **映射到变量空间**：将每个受访者定位到行为变量上
4. **发现行为聚类**：找出变量空间中的聚集模式（2-3人以上重叠）
5. **综合特征+定义目标**：为每个聚类综合行为特征，推导目标
6. **检查完整性**：确保人物模型覆盖所有重要行为模式和目标
7. **指定类型**：主要人物模型（设计主目标）、次要、补充、负面
8. **丰富叙事**：添加名字、照片、日常行为细节，让模型"活"起来

核心区分：人物模型按行为变量聚类，不按人口统计分类。目标是"为什么用"，不是"做什么"。

## A1 — 书中的应用 (Past Application)

### 案例 1: 护士角色差异
- **问题**: 设计医疗产品时，团队认为"所有护士需求类似"
- **方法论的使用**: 用人物模型方法发现外科护士、儿童重症护理护士、手术室护士的行为和目标差异巨大
- **结论**: 用宽泛角色标签代替具体人物模型导致设计定位不清晰——这是"弹性用户"陷阱的具体表现
- **结果**: 证明需要具体的人物模型而非角色标签

### 案例 2: 弹性用户诊断
- **问题**: 团队讨论设计时，"用户"被随意拉伸——需要专家功能时用户变"专家"，需要简化时用户变"新手"
- **方法论的使用**: 用具体人物模型替代弹性"用户"概念，设计决策时问"朱莉会怎么做？"而非"用户会怎么做？"
- **结论**: 人物模型防止设计被强势者的观点拉伸变形
- **结果**: 设计决策获得一致性锚点

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 团队对"我们的用户到底是谁"理解不一致，各说各话
2. 做了用户访谈但不知道如何从数据中提炼设计方向
3. 产品功能越来越多但每个功能都在为不同的"用户"服务
4. 设计评审时有人说"我觉得用户不会这样用"，但无法验证

## E — 可执行步骤 (Execution)

1. **收集行为数据**
   - 从情境调查中获取6-8个用户的访谈/观察数据
   - 完成标准：每个用户有行为描述、目标陈述、痛点记录

2. **识别行为变量**
   - 从数据中提取区分不同用户的行为维度（如：主动vs被动、数据驱动vs直觉驱动）
   - 完成标准：列出5-15个行为变量，每个变量是一个连续谱

3. **映射并发现聚类**
   - 将每个受访者定位到变量空间，找出2-3人以上的聚集
   - 完成标准：每个聚类有明确的行为模式描述

4. **综合特征并定义目标**
   - 为每个聚类综合行为特征，推导体验目标、最终目标和人生目标
   - 完成标准：每个聚类有3层目标 + 行为特征描述

5. **指定类型并丰富叙事**
   - 选择1个主要人物模型（设计主目标），1-2个次要，0-1个负面
   - 添加名字、一天的生活、与产品的交互场景
   - 完成标准：团队能用"XX会怎么做？"做设计决策

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已有明确单一用户群且团队认知一致 → 不需要复杂的人物模型
- 纯营销用途的用户画像 → 营销画像关注购买行为，人物模型关注使用行为
- 资源极少的快速验证 → 用临时人物模型（1页描述+目标），不做完整8步法

### 作者在书中警告的失败模式

- **弹性用户**: "用户"被随意拉伸，团队每个人理解不同
- **自我参考设计**: 设计师把自己的能力和偏好当作用户的
- **边缘功能设计**: 为少数用户的偶尔需求设计主要功能

### 作者的盲点 / 时代局限

- 8步法依赖大量定性研究，对资源有限的项目门槛较高
- 人物模型有效性缺乏严格实验数据支撑
- 在快速迭代的创业环境中，完整8步法可能过于重流程

### 容易混淆的邻近方法论

- 用户画像（营销用）: 关注人口统计和购买行为，不关注使用目标和行为模式
- 用户故事（敏捷用）: 是需求条目，不是设计锚点
- JTBD（Jobs to be Done）: 关注"雇佣"产品的任务，人物模型关注用户的目标和行为模式
