## R (原文)

> "好的导航应该像街头指示牌一样——清晰、一致、无处不在。"
> 
> "面包屑导航告诉用户他们在哪里，以及如何回到起点。"
> 
> "导航的目的是帮助用户找到他们要去的地方，而不是展示网站有多少功能。"

## I (自述)

导航设计的核心是帮助用户在产品中找到方向，减少迷路感。好的导航应该是隐形的——用户不需要思考就能使用。关键在于提供清晰的位置指示和一致的导航模式。

关键洞见：用户在陌生环境中会感到焦虑，清晰的导航能减少这种焦虑，增加用户信心。

## A1 (书中案例)

**正面案例：维基百科**
- 清晰的目录结构
- 面包屑导航显示位置
- 内部链接丰富
- 搜索功能强大

**反面案例：导航迷失的网站**
- 没有面包屑导航
- 页面标题不清晰
- 导航状态没有高亮
- 用户不知道自己在哪里

## A2 (触发场景)

| 场景 | 是否触发 | 理由 |
|------|----------|------|
| 用户反馈找不到页面 | 是 | 导航问题 |
| 网站结构复杂 | 是 | 需要清晰导航 |
| 移动应用设计 | 是 | 导航更重要 |
| 用户迷路率高 | 是 | 导航设计缺陷 |
| 简单单页应用 | 否 | 无需复杂导航 |
| 纯展示页面 | 否 | 无导航需求 |

## E (可执行步骤)

### 步骤1：设计导航结构
- 确定主要导航项
- 限制导航层级（不超过3层）
- 使用用户易懂的命名

### 步骤2：添加位置指示
- 添加面包屑导航
- 设置清晰的页面标题
- 高亮当前导航项

### 步骤3：确保一致性
- 导航位置在所有页面一致
- 导航样式一致
- 交互行为一致

### 步骤4：添加搜索功能
- 提供全站搜索
- 搜索框位置显眼
- 支持模糊搜索

### 步骤5：验证导航效果
- 进行可用性测试
- 测量任务完成率
- 收集用户反馈

## B (边界)

### 适用范围
- 网站导航设计
- 移动应用导航
- 复杂系统导航
- 多页面产品

### 不适用范围
- 简单单页应用
- 纯展示页面
- 无导航需求的产品

### 局限性
- 需要平衡导航深度与广度
- 移动端导航有特殊限制
- 可能受到品牌规范限制
