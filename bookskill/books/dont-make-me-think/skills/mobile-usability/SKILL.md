## R (原文)

> "移动可用性不仅仅是把桌面网站缩小，而是要重新思考用户在移动场景下的需求。"
> 
> "拇指友好区是移动设计的关键——重要操作应该在拇指可触及范围内。"
> 
> "在移动端，内容比导航更重要。"

## I (自述)

移动可用性设计的核心是理解移动端用户的独特需求和使用场景。移动端用户通常在碎片化时间使用，注意力更分散，操作方式也不同（触摸而非点击）。设计必须适应这些特点。

关键洞见：移动端不是桌面端的缩小版，需要根据移动场景重新设计。

## A1 (书中案例)

**正面案例：优步移动应用**
- 简洁的主界面
- 一键叫车（拇指友好区）
- 地图为主，文字为辅
- 操作流程简单

**反面案例：移动端体验差的网站**
- 没有响应式设计
- 文字太小无法阅读
- 按钮太小无法点击
- 导航菜单不可用

## A2 (触发场景)

| 场景 | 是否触发 | 理由 |
|------|----------|------|
| 移动端用户反馈问题 | 是 | 核心需求 |
| 响应式网站设计 | 是 | 需要适配移动端 |
| 移动端转化率低 | 是 | 可用性问题 |
| 移动应用开发 | 是 | 核心场景 |
| 纯桌面端产品 | 否 | 不涉及移动端 |
| 硬件产品设计 | 否 | 非数字产品 |

## E (可执行步骤)

### 步骤1：理解移动场景
- 用户在什么场景下使用？
- 使用时长是多少？
- 使用方式是什么？（单手/双手）

### 步骤2：优化交互设计
- 将重要操作放在拇指友好区
- 按钮尺寸至少44×44像素
- 简化导航结构
- 减少输入操作

### 步骤3：优化内容呈现
- 使用响应式设计
- 确保文字可读（至少14px）
- 图片自适应屏幕
- 避免横向滚动

### 步骤4：优化性能
- 优化页面加载速度
- 减少网络请求
- 支持离线模式

### 步骤5：验证移动端体验
- 在真实设备上测试
- 测试不同屏幕尺寸
- 收集移动端用户反馈

## B (边界)

### 适用范围
- 移动应用设计
- 响应式网站
- 移动网页优化
- 跨平台产品

### 不适用范围
- 纯桌面端产品
- 硬件产品设计
- 非数字产品

### 局限性
- 需要考虑多种设备尺寸
- 需要平衡功能与简洁
- 某些复杂功能在移动端难以实现
