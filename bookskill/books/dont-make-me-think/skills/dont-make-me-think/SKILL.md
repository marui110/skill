## R (原文)

> "当我看一个页面时，我应该能立刻明白它是什么以及怎么用它——不需要思考。"
> 
> "别让我思考——这就是可用性的第一定律。如果我需要思考某个东西是做什么的或怎么用它，那么它就不是一个好的网页设计。"

## I (自述)

Krug可用性第一定律的核心是**自明性**——网页应该像一件设计精良的工具，用户拿起就能用，无需阅读说明书。这不是说要降低功能复杂度，而是要让功能的入口和操作方式变得显而易见。

关键洞见：用户使用网页时的心理状态是"我想要完成任务，越快越好"，任何需要思考的地方都会增加认知负荷，可能导致用户放弃。

## A1 (书中案例)

**正面案例：Google搜索页面**
- 极简设计，只有搜索框和品牌标识
- 用户打开页面就知道该做什么
- 没有任何干扰元素

**反面案例：功能堆砌的企业网站**
- 多个元素争夺注意力
- 用户不知道该看哪里
- 信息过载导致用户困惑

## A2 (触发场景)

| 场景 | 是否触发 | 理由 |
|------|----------|------|
| 用户反馈产品难用 | 是 | 核心可用性问题 |
| 功能入口隐藏 | 是 | 违反自明性原则 |
| 页面改版设计 | 是 | 需要从头考虑可用性 |
| 用户流失率高 | 是 | 可能存在可用性问题 |
| 纯视觉风格调整 | 否 | 不涉及可用性核心 |
| 技术架构优化 | 否 | 纯技术问题 |

## E (可执行步骤)

### 步骤1：检查每个页面元素
- 问自己："用户看到这个需要思考吗？"
- 如果需要思考，标记为需要改进

### 步骤2：评估自明性
- 能否在3秒内理解页面结构？
- 能否一眼看出主要功能入口？
- 交互元素是否明显可识别？

### 步骤3：简化设计
- 删除不必要的元素
- 明确标识可点击的地方
- 使用用户熟悉的模式

### 步骤4：验证改进
- 进行可用性测试
- 收集用户反馈
- 迭代优化

## B (边界)

### 适用范围
- Web网站设计
- 移动应用设计
- 桌面软件设计
- 数字产品评估

### 不适用范围
- 纯艺术设计（无功能需求）
- 复杂企业系统（需要专业培训）
- 硬件产品设计

### 局限性
- 不适用于需要学习曲线的专业工具
- 不能替代用户研究
- 不能解决所有可用性问题

## 检查清单

- [ ] 每个元素都清晰表达其用途
- [ ] 用户能在3秒内理解页面结构
- [ ] 可点击元素明显标识
- [ ] 没有不必要的视觉干扰
- [ ] 使用用户熟悉的设计模式
