## R (原文)

> "用户不会阅读网页，他们会扫读。"
> 
> "如果你想让用户看到你的内容，就必须为扫描而设计，而不是为阅读而设计。"
> 
> "人们在网页上的阅读方式就像在超市里购物——快速扫描，寻找感兴趣的东西。"

## I (自述)

扫读设计法的核心是理解用户的真实阅读行为。用户不是逐字阅读，而是快速浏览页面，寻找关键词和视觉线索。设计必须适应这种行为模式，让用户能够快速找到所需信息。

关键洞见：用户的注意力是宝贵资源，设计应该帮助用户快速定位有用信息，而不是强迫他们阅读所有内容。

## A1 (书中案例)

**正面案例：纽约时报网站**
- 清晰的标题层级
- 头条新闻更醒目
- 使用项目符号列表
- 段落简短

**反面案例：文字冗长的产品页面**
- 大段文字堆砌
- 没有标题层级
- 关键词不突出
- 用户不愿意阅读

## A2 (触发场景)

| 场景 | 是否触发 | 理由 |
|------|----------|------|
| 内容型网站设计 | 是 | 核心需求 |
| 用户反馈找不到信息 | 是 | 扫描体验差 |
| 页面文字过多 | 是 | 需要优化阅读体验 |
| 新闻门户改版 | 是 | 典型应用场景 |
| 简单表单页面 | 否 | 内容量小 |
| 纯交互应用 | 否 | 非信息密集 |

## E (可执行步骤)

### 步骤1：分析内容结构
- 识别核心信息
- 建立信息层级
- 确定关键词

### 步骤2：设计扫描友好的布局
- 使用清晰的标题层级（H1-H6）
- 突出关键词（加粗、颜色）
- 使用项目符号和列表
- 保持段落简短（3-5行）

### 步骤3：优化视觉引导
- 使用视觉层次引导视线
- 创造清晰的视觉模式
- 使用空白分隔内容块

### 步骤4：验证扫描效率
- 进行眼动测试
- 测量信息查找时间
- 收集用户反馈

## B (边界)

### 适用范围
- 新闻网站
- 博客文章
- 产品列表页
- 文档页面
- 内容密集型页面

### 不适用范围
- 简单功能页面
- 交互型应用
- 纯视觉展示
- 表单页面

### 局限性
- 不适用于需要精读的内容（如法律文档）
- 不能替代内容质量本身
- 需要配合其他可用性原则
